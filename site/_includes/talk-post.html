Video source — first match wins: 1. `bilibili: "BVxxxxxxxxxx"` (+ optional `bilibili_page: N` for a multi-part upload). Preferred. Renders a click-to-load facade (poster + play button) that swaps in the real Bilibili iframe player only after a click, so the third-party player never loads a single byte until the visitor asks for it. The facade is a real link to the Bilibili watch page, so it still works with JavaScript disabled — progressive enhancement, not a hard dependency. 2. `video: "/assets/media/...mp4"` — legacy/local fallback for a talk that has not been uploaded to Bilibili yet. Same player as before. 3. Neither — a static, honestly-labelled cover image ("Video coming soon"). Never a play button that leads nowhere. `poster` sets the still image for all three modes. Optional `poster_fallback` is used as an `onerror` fallback if `poster` points at a remote URL that may fail to load (e.g. hotlinked cover art).
